# Contributing findings and ideas

Participants are encouraged to share what they found, tried, and built during the atelier.
Contributions live in `submissions/` folders inside each test directory.

---

## How to submit

1. **Fork the repository** on GitHub.
2. **Copy** the `TEMPLATE.md` from the relevant test's `submissions/` folder.
3. **Rename** the copy to `{your-github-handle-or-team-name}.md`
   (e.g. `team-alpha.md` or `jsmith.md`).
4. **Fill in** what you tried, what you found, and any open questions. Delete sections that do not
   apply — partial findings are welcome.
5. **Open a pull request** targeting `main`.

For code patches, prototypes, or modified FHIR JSON files, put them in
`submissions/prototypes/{your-handle}/` instead of (or alongside) the markdown file.

---

## Filename conventions

| What | Where | Name |
|------|-------|------|
| Findings (markdown) | `submissions/` | `{github-handle-or-team}.md` |
| Code / patches / modified files | `submissions/prototypes/{handle}/` | any |

Using your GitHub handle or a unique team name avoids filename collisions when multiple groups
submit to the same folder.

---

## What to include

The `TEMPLATE.md` in each test's `submissions/` folder has optional sections — delete what does
not apply. There is no requirement to fill everything in. A few bullet points of "we noticed X"
or "we got stuck on Y" are more useful than silence.

---

## No requirement to finish

These are bonus exercises. A submission saying "we started exploring X, got stuck on Y, and
think Z is the right next step" is a valid and welcome contribution.
